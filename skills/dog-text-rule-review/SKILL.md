# 完成版とドラフトを比べて、生成ルールの更新案を出す

作業場所は `/Users/daiki/Desktop/Dog Text`。完了案件は `/Users/daiki/Desktop/Dog Vrew/cases/<case-id>/`、
ドラフトは `runs/<run_id>/script_*_*.txt`、ルールブックは `rules/ゴシップ台本生成ルールブック.md`。

**手順の正本はルールブック末尾近くの「完成版を分析して規則を作るときの制約」1〜6である。**
このスキルはそれを抜かさず順に踏ませる入口で、中身を写したものではない。食い違ったら制約の節が正しい。
踏む前に、その節を毎回読み直す（第何回まで進んでいるか、却下一覧と保留一覧が変わっていないか）。

```bash
cd "/Users/daiki/Desktop/Dog Text"
grep -n "## 完成版を分析して規則を作るときの制約" rules/ゴシップ台本生成ルールブック.md
grep -n "^\*\*2026" rules/ゴシップ台本生成ルールブック.md | tail -3    # 最新の回
```

## 分析の手順

### 1. 新しい完了案件と、対応するrunを特定する

- 除外表 `lib/excluded_cases.rb` に載っている案件は、手本にも分析にも使わない（制約の末尾・第61回）。
- 新しい案件が、どの版のルールブックで生成されたかを `runs/<run_id>/rules_provenance.json` で見る。
  直前の回で入れた規定が効いたかどうかを、最初に確かめる（効いていなければそれ自体が報告事項）。

### 2. 3つの道具を回す（制約6）

```bash
ruby tools/scan_open_close_rev1.rb                 # 冒頭・最終行の事実を、ドラフト4本が同じ位置に置けたか
ruby tools/scan_open_close_rev1.rb --case CASE_ID  # 新しい案件を詳しく
ruby tools/scan_phrases_rev1.rb                    # 見張り語の使用率（全件と09-13以降）
ruby tools/scan_phrases_rev1.rb --discover         # 使用率の差が大きい言い回し
ruby tools/scan_rewrites_rev1.rb --case CASE_ID    # 引用・事実の錨で取った書き換え表
ruby tools/scan_rewrites_rev1.rb                   # 全件の書き換え表
```

- **いちばん近いドラフト1本とだけ比べない。**4本のうち何本が完成版と同じにできたかで判断する。
- **書き換え表は数えるだけでなく全行読む。**1回きりの書き換えは数えると埋もれる。
- 冒頭・最終行・つなぎの行は、**改行の仕方**（1行にまとめたか、分けたか）も比べる。
- 本数が低い回や、繰り返される書き換えがあれば、**ルールブックに名前の無い型でも案にする。**既存の分類に当てはめて読み流さない。

### 3. 出してよい案かどうかを照らす

- **制約1**：判定材料が生成時点に無いもの（結びのネットの声、元記事の原文、案件の完成版）を使う規則は作らない。
- **制約2**：完成版が文字起こしと食い違っても、それだけで逸脱と判定しない。
- **制約3**：**削る方向の案は出さない。**ドラフトより短い・素材が減った・一文が消えた、は運用の結果であって差分ではない。
  言い回しの差でも、ドラフト側が多いものは削った結果と区別できないので、置き換えと分かったときだけ案にする。
  「言い直しだから素材ではない」という判断を分析側でしない（第65回で却下された前例）。
- **制約4**：**却下一覧に載っている案は二度と出さない。**
- **制約5**：**保留一覧の案は、今回の新しい実例が根拠を1件以上増やしたときだけ出す。**増えていなければ出さない（「前回からの継続」として再掲しない）。
- 1件だけの観察は案にしない。報告に回す。

### 4. 報告の形

- 最初に、新しい案件で直された箇所を表にする（ドラフト → 完成版）。
- 案ごとに：何を変えるか／根拠の件数（完成版とドラフトの本数・使用率）／**「ドラフトの言い方 → 完成版の言い方」の実例**／今ある規定との関係／懸念。
- 案にしなかったものは、理由（1件だけ、削る方向、却下済み、保留で根拠が増えていない）を添えて短く並べる。
- 保留案は、根拠が増えていないなら**一覧にも書かない**。
- この段階ではルールブックを変えない。ユーザーがどれを入れるか決める。

## 採用された案を反映する手順

1. **退避を取る。**本体を書き換える直前に、1回だけ撃つ（本体が変わっていないのに撃たない）。

   ```bash
   ruby "/Users/daiki/Desktop/Dog Vrew/tools/rule_backup_rev1.rb" take rules/ゴシップ台本生成ルールブック.md --reason 英数字と_の理由
   ```

2. **ルールブックを書き換える。**条文に【日付・第N回】を付け、根拠の件数と実例（ドラフト → 完成版）を条文そのものに書く。
   必要なら 2-3語彙バンク・2-4・Part4チェックリストも合わせて直す。末尾の変更履歴に「第N回」を足す
   （見出しは `**YYYY-MM-DD（第N回更新）**：` の形。生成時の版表記はここから取られる）。
   却下された案は制約4の一覧へ、保留にした案は制約5の一覧へ件数つきで移す。
   - 日本語を含む Python をヒアドキュメントで流すと文字化けして失敗することがある。スクリプトはファイルに書いてから流す。
3. **機械で判定できる規定は検査器（`lib/script_validator.rb`）にも入れ、`tools/test_script_validator_rev1.rb` にテストを足す。**
   実データで、完成版にはほとんど警告が出ず、ドラフトには出ることを確かめる。置く場所の規定のように語の有無で判定できないものは、検査器に入れない。
4. **全テスト → ビルド → 退避の点検。**

   ```bash
   for t in tools/test_*.rb; do printf "%s: " $t; ruby "$t" 2>&1 | tail -1; done
   bash build_drop_app.command      # 末尾でDropboxへの退避も走る
   ruby "/Users/daiki/Desktop/Dog Vrew/tools/rule_backup_rev1.rb" scan
   LANG=ja_JP.UTF-8 ruby -r ./lib/script_builder -e 'p ScriptBuilder.provenance["rulebook"]["revision"]'
   ```

5. 分析手順そのものを直したときは、制約の節と、プロジェクトの `CLAUDE.md` の「完成版とドラフトを比べて規則を作るとき」節と、**このSKILL.md**を同じ回で直す。道具を足したら手順2のコマンド一覧にも足す。

## 実例を除外すると言われたとき

`lib/excluded_cases.rb` に登録し、`ruby tools/prune_examples_rev1.rb rules/ゴシップ台本実例.txt <例番号>` で実例から消す（先に `rule_backup_rev1.rb take rules/ゴシップ台本実例.txt`）。
`ruby tools/append_case_example_rev1.rb --scan` が「未反映の完了案件は無い」を返すことを確かめ、変更履歴に記録する。
