# 引用元の動画を X で探す

付属の `find_source.rb` が4つの工程を受け持つ。標準 Ruby 2.6 と curl のほかに、次のものを使う。

- ffmpeg：`~/Desktop/Dog Tools/【work】/YT DL/bin/ffmpeg`
- yt-dlp と deno：`~/Library/Application Support/Dog React/bin/`
- ログイン済みの**デバッグ用 Chrome**（CDP 9333、`~/.dog_imagine_chrome`）

作業フォルダ（`--work`）は scratchpad に切る。

## 決まり（だいきんぐの指示）

- 照合する候補は**100本まで**（`--limit 100` が既定）。それ以上は検索を広げない。
- 一致する投稿が無ければ「なかった」で終わらせない。**一致度の高い順に5本**を、投稿URL・日時（日本時間）・本文つきの表で出す。
- 別公演や別グループの投稿（フレオ祭・AKB など、検索語にたまたま引っかかったもの）は、目で見て5本から外す。外したことは一言書く。
- 候補を出せと言われたら、その場でコマの画像（SendUserFile）と投稿の一覧を出す。照合の途中でも、先に出してから続ける。

## 手順

### 1. 参考動画を落として、区間と切り出し位置を決める

```bash
ruby ~/.claude/skills/clip-source-finder/find_source.rb prep "<動画URL>" --work <DIR> --from 22 --to 31
```

- 区間（`--from` / `--to`）はだいきんぐが言った秒から、素材が切り替わる所までにする。`range.png`（2秒おき）を見て、同じ素材が続いている所だけに絞る。途中で静止画など別の素材に変わるなら、そこで切る。
- 説明欄のリンクも出る。ただし反応集チャンネルの説明欄にあるのは**自分の過去動画**のことが多く、引用元とは限らない。タイトルを見て判断する。
- `frame.png`（原寸の1コマ）を見て、集中線やテロップを除いた**素材の枠**を `W:H:X:Y` で読む。ワイワイ速報の 360x640 では `306:472:27:88` だった。枠がずれると一致度が大きく落ちるので、ここは必ず目で決める。
- 透かしやクレジットが写っていれば、それが一番早い手がかり。先に見る。
- 素材の中身（誰が・どの公演・どの曲・衣装・天気）は WebSearch で当たりをつけ、検索語と期間（`--since` / `--until`）を決める。

### 2. X を検索して候補を積む（上限100本）

```bash
ruby ~/.claude/skills/clip-source-finder/find_source.rb search --work <DIR> --since 2026-06-20 --until 2026-07-15 "佐々木舞香 国立" "舞香 雨 国立" "お姫様の作り方 舞香" "#イコラブ国立 舞香"
```

- `filter:videos` は勝手に付く。既定は「話題」タブで、`--latest` を付けると「最新」タブになる。
- 検索語は、人名＋会場、愛称＋状況（雨・リフト等）、曲名、ハッシュタグの組み合わせで3〜5本にする。候補は `candidates.json` に積み増しされ、100本で止まる。
- 「X にログインしていない」と出たら、デバッグ用 Chrome で X にログインし直してもらう。パスワードは私が入れない。アプリ内ブラウザや Claude in Chrome は X にログインしていないことが多い。

### 3. 本文と動画を取る

```bash
ruby ~/.claude/skills/clip-source-finder/find_source.rb fetch --work <DIR>
```

api.fxtwitter.com から取るのでログインは要らない。動画は下から2番目の画質で落とす（照合には十分）。

### 4. 照合

```bash
ruby ~/.claude/skills/clip-source-finder/find_source.rb match --work <DIR> --crop 306:472:27:88
```

- 区間のコマ（2fps）と候補動画のコマ（2fps）を 24x36 のグレーに縮め、正規化相互相関の最大値を比べる。上位6コマの平均がその候補の一致度になる。
- 候補は参考側と同じ縦横比で中央を切り、拡大率 1.0・0.87・0.75 の3通りで測る。反応集は素材を拡大して使うことが多いため。
- **0.80 以上なら一致**。自己検証では、15%拡大して枠にはめた同じ映像が 0.999 だった。別物は 0.5〜0.71 に収まる。
- 一致が無ければ上位10件が出る。`top.png`（1段目が参考の区間、2段目以降が上位の候補）を目で見て、別公演・別グループを外し、5本にして表で出す。
- 1位の一致度が 0.75 前後で2位と大きく離れているときは、枠（`--crop`）のずれを疑う。`frame.png` を見直して測り直す。

## 結果の出し方

- 一致したとき：投稿URL・投稿者・日時（日本時間）・本文・いいね数と、どの区間がどの投稿か。
- 一致しないとき：「見つからなかった」と先に書いてから、一致度つきの上位5本の表を出す。調べた範囲（検索語・期間・本数）も書く。次の手（TikTok・「最新」タブ・投稿者の別投稿）は1〜2行で添える。
- 静止画の素材（報道写真など）はこのスキルの照合の対象外。公演名と写真の出どころ（ナタリーのレポート等）を WebSearch で当てる。

## 踏んだ所

- yt-dlp は `--js-runtimes deno:<path>` を付けないと YouTube の形式が一覧に出ず、「Requested format is not available」で落ちる。スクリプトでは付けてある。
- ffmpeg で大きさの違う画像を `-pattern_type glob` のまま tile すると、1枚目以外が抜ける。一度そろえた大きさに縮めてから並べる。
- Ruby は `LANG` 無しだと日本語のパスで落ちる。スクリプトの冒頭で UTF-8 に寄せてある。
