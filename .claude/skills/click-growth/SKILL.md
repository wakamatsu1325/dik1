# 投稿のクリック数の伸びを分析する

作業場所は `/Users/daiki/Desktop/Dog URL`。記録は `~/Library/Application Support/Dog URL/` の
`clicks.json`（取得時刻と累計）、`history.json`（短縮URLの履歴）、`runs/*.json`（投稿の実行記録）。

## 手順

### 1. 対象のクリック数を今読む

記録は押したときの値しか無いので、先に最新を積む。対象の指定が無ければ最新の投稿（`runs` で一番新しいもの）。

```bash
cd "/Users/daiki/Desktop/Dog URL" && ruby bin/shorten.rb stats <短縮URL> --with-post   # https://x.gd/<ID> か https://tinyurl.com/<alias>
```

最新の投稿の短縮URLが分からなければ、先に手順2を引数なしで流すと先頭に出る。
`timeout` コマンドは無い（macOS）。付けない。

### 2. 全投稿と比べる

```bash
ruby ~/.claude/skills/click-growth/analyze.rb            # 最新の投稿
ruby ~/.claude/skills/click-growth/analyze.rb <alias>    # 指定
```

読むだけで何も書かない。出るもの:

- 対象の区間ごとの増分（どこで失速・加速したか）
- 20分・40分・80分・3時間・6時間…の各節目で、**全投稿の中で下から何番目か**と中央値
- 節目の間にいるときは「今（N分）」の行で、今の経過時間での順位も出る。節目の値が `-` でもこの行で位置が言える
- 24時間の数の分布（中央値）
- **今の経過時間**→24時間の倍率から出した見込みと、それが分布の何番目に当たるか。
  節目まで戻らず今の値で出す（節目のあとの失速・加速を捨てないため）。倍率を手で計算し直さなくてよい
- 次の節目での分かれ目（24時間で中央値以上だった投稿と未満だった投稿が、その節目でいくつだったか）
- 24時間で上位1/4だった投稿の序盤（逆転の前例があるか）

## 比べ方の決まり

- 2026-09-25 以降の投稿は、アプリが投稿80分後と3時間後に自動で1回ずつ読んでいる（`clicks.json` の `mark: "m80"` / `"m180"` の行）。
  80分・3時間の比較はこの行でそろう

- **60分以内に出し直した投稿は、起点が出し直しの時刻に移る**（2026-09-29 から）。前の投稿を消して出し直した回に、消えた投稿の時刻で数えないため。
  古い `mark: post` は `post_superseded` に、その起点をきっかけにした `neighbor`（phase post）は `neighbor_superseded` に印が替わって残る。
  分析側（analyze.rb）は無改造で新しい起点を拾う（`mark == "post"` だけを見ているため）。
  それ以前の回は移っていない。出し直しの疑いがあれば `runs` の同じ `short_url` の複数件と、Bluesky に前の投稿が残っているかで確かめる
- **一部ではなく全投稿と比べる。** 直近の数件だけで判断しない
- **物差しが2種類ある**（2026-09-29 から）。それまでの TinyURL は同じ回線のクリックを1件に丸めて少なめに出る。X.gd は踏んだ回数どおり数える。
  スクリプトは対象と同じ物差しの投稿が5件以上あればそれだけと比べ、足りなければ全部と比べて ⚠ を出す。
  **⚠ が出たら、順位や見込みは「TinyURL 時代より多めに出る物差しでの目安」と断って答える。** X.gd の対象が上位に出ても、それだけで「伸びた」と言わない。
  X.gd の投稿が5件たまるまでは、X.gd 同士の比較（件数を添える）も並べて言う
- 投稿間隔（`--interval`）は前の投稿自身の伸びの比なので、物差しの違いは比にほぼ効かない。ただ「同格の目安」は累計で強さをそろえるので、物差しをまたぐ組は同格の判定がずれる
- **経過時間をそろえる。** 起点は投稿時刻の記録（`mark: post`）、無ければ短縮URLの生成時刻
- 記録は間隔がまばら。スクリプトは前後の記録の間が狭いとき（40分か、節目の半分の長い方まで）だけ補間し、広いときは ±25% 以内の実測の最寄りを
  `36(79分)` のように分数付きで出す。**`-` の節目は比べられないので埋めない**
- 外すもの（スクリプトが末尾に出す）:
  - 子リンク（投稿の実行記録に紐づかないURL。Cの返信内など）
  - 序盤（投稿後60分以内）の記録が無い初期の投稿（09-10以前）。実際に投げたかも怪しいものが混ざる

## 読み方の決まり

- **良し悪しは24時間の分布で決める。** 中央値未満は「悪い」、下位1/4は「かなり悪い」。
  **24時間で中央値に届かなかった投稿を「伸びた」「挽回した」と呼ばない**
  （24→179 は倍率こそ高いが、24時間で下位。逆転の例ではない）
- 逆転の前例として挙げてよいのは、**序盤が中央値以下で24時間が上位**に入った投稿だけ。
  「上位1/4の序盤」欄に該当が無ければ、「逆転の前例は無い」とはっきり言う
- 見込みは倍率の最低〜最高の幅と中央で言う。中央の見込みが分布で何番目かを添える（最下位なら最下位と言う）
- 最後に**次の節目での判断の目安**を1つ出す（例: 3時間で85未満なら中央値未満で終わった投稿しかない）。
  数字はスクリプトの「分かれ目」欄から取る。件数が少ないことは断る
- 「記録の直近の区間が +0」は反映遅れのことが多い（X.gd は5〜10分、TinyURLは1分前後）。失速と決めつけない。
  X.gd の80分・3時間の定点は、実質70〜75分・2時間50分ごろまでのクリックである
- 80分・3時間の自動取得（`m80` / `m180`）が抜けていたら、アプリが終了していた（⌘Q・再起動・ビルドし直し）疑いが強い。
  2026-09-27 からは窓を閉じても終了しない（Dock に残って予約を続ける）。それ以前は窓を閉じると終了していた。
  抜けたことと、その節目は比べられないことを答えに書く。原因は `log show --predicate 'process == "DogURLApp"'` で終了時刻を見れば分かる
- 深夜（23時〜翌5時）に投げた投稿は、序盤の節目が深夜に当たる。日中の投稿と同じ物差しで悪いと決めず、時間帯を添える

- 複数の投稿を頼まれたら、1件ずつ手順1・2を流す。冒頭に全件の一覧表（投稿時刻・経過・投稿後の数・評価）を置く
- 投稿間隔（新しい投稿が前の投稿の伸びを止めるか）に触れるときは、**必ず `analyze.rb --interval` を流して、その出力だけを根拠にする**。
  会話の中で手で拾った前後の数字を根拠にしない（引き継げず、補間で比が1に寄るなどの誤りも混ざる）。手順は下の「投稿間隔の検証」

## 投稿間隔の検証

```bash
ruby ~/.claude/skills/click-growth/analyze.rb --interval
```

新しい投稿 N を出した時刻 T の前後で、直近48時間以内に投げた前の投稿 P の1分あたりの伸びを比べる。
結果は会話に残さなくても、`clicks.json` から毎回同じものが出る（別セッションでもこれを流せば続きになる）。

- **材料はアプリが自動で積む**（2026-09-26 から）。新しい投稿を投げ終えた瞬間と、その80分・3時間の定点で、
  直近48時間の前の投稿の累計も読む（`mark: "neighbor"`、`by` にきっかけの投稿、`phase` に post / m80 / m180）。
  それ以前の組は、たまたま T の前後15分に記録がある回しか判定できない
- 前の伸び: T の約80分前の記録 → T。後の伸び: T → 約80分後の記録。T の値は neighbor の行か、T±15分の実測。**補間はしない**
- 投稿は放っておいても伸びが落ちる。そこで**自然減の目安**（他の投稿が同じ経過時間の前後80分をどう動いたかの後/前の中央値。
  その間に別の投稿が出ていない回だけ）と比べ、0.7倍未満なら「落ちた」、1.3倍超なら「保った」、間は「自然減なみ」
- **判定に使うのは「同格の目安」**（2026-09-28 から）。同じ経過時間での累計が、前の投稿の 1/2〜2倍 の投稿だけで作った目安。
  全体の目安だけだと、弱い投稿が普段から早く落ちるだけで「落ちた」と出て、新しい投稿のせいかを切り分けられないため
  （全体の目安で判定した10組のうち「落ちた」6組が、全部24時間で中央値未満の投稿だった）。
  強さは T の時点で分かる累計で測る。24時間の成績で絞らない（干渉の結果そのもので絞ることになる）。
  出力には全体の目安での判定も `[全体: …]` として並ぶが、**結論には使わない**
- **判定するのは**、前の投稿が1分0.1件以上伸びていて、同格の目安が2件以上ある組だけ。他は「判定外」と出る
- 残る交絡: 新しい投稿を出す時刻は夜に偏るので、時間帯の影響はまだ切り分けていない。結論を言うときはこれを添える
- 答えるときは: 判定できた組数と内訳（落ちた／なみ／保った。同格の目安のもの）、各組の間隔と前の投稿の経過時間を出す。
  スクリプトが「前の投稿が投稿から3.5時間以内／それ以降」に分けた内訳も出すので、それを使う。
  **判定できた組が10組に満たないうちは結論を出さない**（「傾向の候補」まで）。
  前の投稿がまだ強く伸びている時間帯（投稿から3時間以内など）の組と、もう下り坂の組を分けて見る

## 答え方

1. 冒頭で**結論を1〜2文**（全投稿で何番目・24時間の見込み・良いか悪いか）
2. 区間ごとの伸び（短い表）
3. 節目ごとの順位と中央値（表）
4. 24時間の見込みと、その根拠の倍率
5. 逆転の前例の有無
6. 次の節目の目安と、1〜2時間後にもう一度読むかどうか

注意書きは最小限にする（除外したものと起点の扱いを1行ずつ。物差しの ⚠ が出たらそれも1行）。
