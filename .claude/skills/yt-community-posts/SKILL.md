# YouTube コミュニティ投稿の取得

付属の `yt_posts.rb` が全部やる。ログイン・APIキー不要、標準Ruby 2.6 と curl だけ。
**私の側では組み立て直さない。** URLを渡して走らせ、出力の要約行をそのまま伝えるだけにする（使用量を抑えるため）。

## 実行

```bash
ruby ~/.claude/skills/yt-community-posts/yt_posts.rb "<チャンネルURL or @handle>" ["<2つ目>" ...]
```

- ブラウザのブックマークフォルダごと回すとき（サブフォルダも含め、重複は除く）：

  ```bash
  ruby ~/.claude/skills/yt-community-posts/yt_posts.rb --bookmarks <書き出したブックマーク.html> --folder <フォルダ名> [--list]
  ```

  Brave/Chrome のプロファイル（`~/Library/Application Support/BraveSoftware/...`）は macOS の保護で**サンドボックス外からも読めない**。ブックマークマネージャ（⌘⌥B）→「⋮」→「ブックマークをエクスポート」で HTML に書き出してもらう。先に `--list` で件数と中身を見せてから回す。取り直し不要と言われたチャンネルは `--skip <ブックマーク名かURLの一部>`（何度でも）で外す。
- **特定の投稿だけ**（`youtube.com/post/<ID>` や `…/community?lb=<ID>`。`?si=` 付きのままでよい）：同じコマンドに投稿URLを渡す。**画像だけ**を `~/Desktop` の直下へ落とし（名前は同じ `高評価数_本文1行目_N.拡張子`）、txt もフォルダも作らない（だいきんぐの指定）。置き場を変えるなら `--out DIR`。チャンネルURLと混ぜて渡してもよい。

  ```bash
  ruby ~/.claude/skills/yt-community-posts/yt_posts.rb "https://youtube.com/post/<ID>"
  ```

- **クラウド環境（`~/Desktop` が無い）の共通の保存先は、リポジトリ直下の `downloads/`**（`/home/user/dik1/downloads`。`.gitignore` 済み）。`--out` を付けなくてよい。個別の投稿は `downloads/` 直下、チャンネルは `downloads/コミュニティ投稿/<チャンネル名>_投稿/`。スクラッチパッドなど別の場所へ落とさない。クラウドのコンテナは一定時間で破棄されるので、取得後はユーザーに保存先を伝える。
- URL は `/posts` `/videos` 付きでも、チャンネルトップでも、`@handle` だけでもよい（日本語の @handle もそのまま渡せる）。
- 1チャンネル200件・600枚で約30秒。**複数チャンネルは1回の呼び出しに並べ、`run_in_background` で走らせて完了通知を待つ**（途中で出力を覗かない）。
- 保存先の親を変えるときだけ `--out DIR`（既定はチャンネルなら `~/Desktop/コミュニティ投稿`、個別の投稿なら `~/Desktop`。クラウドは上記 `downloads/`）。

## 出力の形（だいきんぐの指定）

`~/Desktop/コミュニティ投稿/<チャンネル名>_投稿/` の**直下**に（デスクトップ直下に何十個も並べないため、親を1つ挟む）。投稿0件のチャンネルはフォルダを作らない：

- 画像：`高評価数_本文1行目_N.拡張子`（例 `3874_レトロ水着の彼女が部屋では…😍_1.jpg`）。拡張子は中身に合わせる（jpg/png/gif）。画像は `=s0` の元画像（クロップなし）。
- **GIFはアニメGIFのまま保存する**（だいきんぐの指定）。静止画や mp4・webp へ変換しない、1コマ目だけ切り出さない。`=s0` なら元のアニメGIFがそのまま返る（実測：1枚136コマ・約25MB）。サイズ指定（`=s1080` など）へ変えたり、落とした後に ffmpeg や sips を通したりする改修はしない。報告ではGIFのコマ数を添える。
- `投稿一覧.txt`：全投稿を新しい順に1本へ。投稿ごとに 見出し・本文・高評価数・投稿日時・投稿URL・投稿ID・画像名と元URL。区切りは `=====` の行。
- **アンケート投稿は取らない**（だいきんぐの指定）。前に保存したアンケートがあれば、取り直しのときに画像ごと消す。アンケートしか無いチャンネルはフォルダを作らない。動画を貼った投稿は `動画:` 行にURL。
- 本文から **URLだけ** 消す（`👉` などは残す）。json は作らない。投稿ごとのtxtもフォルダも作らない。

## 取り直し

同じチャンネルをもう一度走らせると：
- 高評価数が変わった画像は**付け直す**（リネーム。落とし直さない）。新しい投稿の画像だけ落とす。
- 今回の一覧に出なかった過去の投稿（削除・上限で切れた分）は、画像も記録も消さずに一覧の末尾へ残す。
- 対応づけは前回の `投稿一覧.txt` の「投稿ID」と画像名で取るので、**この txt の書式を手で崩さない**。

## 投稿URLを渡されたとき：画像の出力後に Bluesky 本文のURLをチャットへ出す（毎回）

個別の投稿（`youtube.com/post/…`）を取って画像をチャットへ出したら、**その後に必ず**、投稿本文のリンク先（Bluesky の投稿）の**本文にあるURL**をチャットへ出す（だいきんぐの指定）。スクリプトは本文のURLを消すので、別に調べる。

1. 投稿ページから本文のリンクを取る：

   ```bash
   curl -sL -A "Mozilla/5.0" "https://www.youtube.com/post/<ID>" -o p.html
   grep -o '"text":"[^"]*http[^"]*"' p.html | head -1   # 本文（bsky.app/profile/…/post/<rkey> が入っている）
   ```

2. Bluesky の API で、その投稿の本文とリンク（facets）を読む。handle は DID に解決されるので、そのまま `at://<handle>/app.bsky.feed.post/<rkey>` でよい：

   ```bash
   curl -s "https://public.api.bsky.app/xrpc/app.bsky.feed.getPostThread?uri=at://<handle>/app.bsky.feed.post/<rkey>&depth=0"
   ```

   `record.facets[].features[].uri`（リンク）と `record.text`（本文）を見る。

3. チャットへ `https://x.gd/xxxxx` の形で出す（本文が `x.gd/xxxxx` と省略形でも `https://` を付けて出す）。
4. **頼まれなくても毎回**、そのURLの転送先まで踏んで（`curl -sI -A "Mozilla/5.0" <URL> | grep -i -E '^(HTTP|location)'`、`location` を最終ページまで繰り返し、ページ本体は開かない）、転送先のURLもチャットに出す（だいきんぐの指定）。
5. 本文にリンクが無い・Bluesky ではない・取れないときは、その旨を一言書く（黙って省略しない）。

## 報告と注意

- 出力の要約行（件数・最古の投稿・新規/付け直し/失敗）をそのまま伝える。
- **ちょうど200件**なら警告が出る。ログインなしの上限で古い投稿が切れている可能性がある（女性芸能人の裏雑学で実測、最古「3 か月前」で続きが途切れた）。真偽はブラウザで最下部までスクロールして確かめるしかないと伝える。
- 投稿日時は YouTube の相対表記（「3 か月前」）しか取れない。取得時刻を添えて記録している。
- 「ページを読めない」は、たいていチャンネルが消えている（404）。連続で回すとたまに一時的にも起きる（3回まで読み直す）ので、そのチャンネルだけもう一度走らせて確かめる。
- 取得失敗の画像は一覧に `（取得失敗）` と書かれる。もう一度走らせれば落とし直す。

## 仕組み（直すとき用）

- 1ページ目は `/posts` の HTML の `ytInitialData`、続きは `youtubei/v1/browse` に continuation token を投げる。
- **token は投稿（`backstagePostThreadRenderer`）と同じ配列にある `continuationItemRenderer` のものだけを使う。** ページ内の別の continuation（チャンネル概要）を拾うと、10件で止まる（実際に踏んだ）。
- 本文のリンクは `navigationEndpoint` を持つ run なので、その run ごと落としている。
